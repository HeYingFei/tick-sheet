# 运行时配置外置 设计方案

日期：2026-09-22

## 目标

把前端请求的后端地址从构建产物里挪到一个外置文件，使**改地址不需要重新打包**。

## 现状与问题

`frontend/src/api/request.js` 中后端地址在**构建时**确定：

```js
const API_BASE_URL =
  import.meta.env.VITE_API_BASE_URL ||
  `${window.location.protocol}//${window.location.hostname}:8080/api`
```

- `VITE_API_BASE_URL` 是构建时注入的变量，改它必须重新构建
- 项目里没有任何 `.env` 文件，所以实际走的是「当前页面主机名 + 8080」这条兜底
- 该兜底在局域网直连场景下恰好可用，但它假设「前端与后端跨源、后端单独占 8080」

交付或换机时，后端地址一变就得重新构建、重新部署整个前端。

## 方案选型

考虑过三种做法：

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A | 照搬参考项目：`public/apiConfig.js` 顶层 `const` + `document.write` + `Math.random()` 防缓存 | 否。裸标识符没有声明处；`document.write` 阻塞解析；`Math.random()` 让该文件永不缓存 |
| **B（采用）** | `public/apiConfig.js` 挂 `window.__TICKSHEET_CONFIG__`，用静态 `<script>` 加载 | 采用。改动最小，加载顺序有保证，不需要额外的防缓存手段 |
| C | `public/config.json` + 应用挂载前 `fetch` 异步加载 | 否。需要把 `axios.create({ baseURL })` 的求值时机挪到请求拦截器，动了请求层核心逻辑，收益有限 |

## 设计

### 文件职责

| 文件 | 职责 |
| --- | --- |
| `frontend/public/apiConfig.js` | 唯一的现场可编辑入口，默认值为空 |
| `frontend/index.html` | 在 module 脚本之前**同步**加载 `apiConfig.js` |
| `frontend/src/api/request.js` | 按三级优先级解析后端地址 |

### 取值优先级

```
外置配置 apiConfig.js  >  构建时 VITE_API_BASE_URL  >  主机名 + 8080 推导
```

| 场景 | 配置值 | 结果 |
| --- | --- | --- |
| 局域网直连（当前） | 留空 | 按页面主机名连 8080，行为与改动前完全一致 |
| 后端换机器 | `http://192.168.1.50:8080/api` | 直接生效，无需重新构建 |
| 同源反向代理 | `/api` | 相对路径请求，一份产物即可用 |

### 为什么用静态 `<script>` 而不是 `document.write`

文档中 `type="module"` 的脚本默认是 deferred 的，而传统脚本解析到即执行。因此只要把 `<script src="/apiConfig.js"></script>` 放在 module 脚本之前，配置就必定先于应用代码就绪，无需动态插入。

关于缓存：静态服务器默认对文件发条件请求（`If-Modified-Since` / `If-None-Match`），文件内容变了就返回新内容，所以「改了地址刷新即生效」并不需要 `Math.random()` 这种让文件永不缓存的激进手段。

### 错误处理

以下三种失效情况都静默降级到下一级优先级，应用照常启动：

- 文件不存在
- 文件语法错误（传统脚本的语法错误不会影响后续的 module 脚本）
- 字段为空或未填写

额外：若 `window.__TICKSHEET_CONFIG__` 整体不存在，控制台打印一条 `console.warn`。现场最常见的困惑是「我改了地址为什么不生效」，有这条提示便于定位。

### 边界（本次不做）

- 不改 `base` / `outDir`
- 不改输出文件名策略，保留 Vite 默认的 `[hash]`。内容哈希已能精确失效；再叠加构建时间戳会让每次构建全量资源重新下载
- 不改 `VITE_API_BASE_URL` 的既有语义，只在其之上增加一级更高优先级的覆盖
- 不引入 `@vitejs/plugin-legacy`。本项目使用 `backdrop-filter` 等现代特性，IE11 无法渲染，引入只会让产物体积翻倍

### 仓库安全

`apiConfig.js` 会随仓库公开，因此默认值必须是空字符串，不得包含任何真实局域网地址。

## 验证方式

1. `npm run build` 后确认 `dist/apiConfig.js` 存在
2. `apiConfig.js` 留空，确认请求按页面主机名 + 8080 发出（与改动前一致）
3. 填入一个具体地址，确认请求确实打到该地址
4. 故意写坏语法，确认应用仍能启动并降级到下一级

# TickSheet

**一个自托管的个人任务管理系统。**

四象限优先级、操作时间线、多维统计，配合按用户隔离的数据层与完整的导出/备份能力。
前端为单页应用，后端提供 REST 接口，数据库结构由 Flyway 版本化管理。

## 功能特性

### 任务管理

- **四态状态机** —— 待办 / 进行中 / 已完成 / 已取消，流转路径由白名单强制校验，非法流转直接拒绝；重复提交同一状态视为幂等空操作。
- **乐观锁** —— 任务带 `version` 字段，并发编辑时后提交的一方收到 `409`，不会静默覆盖他人修改。
- **软删除 + 全量留痕** —— 删除只置标记位；创建、编辑、流转、象限变更、恢复等每个动作都写入操作日志，构成时间线数据源。
- **字段级变更明细** —— 日志以 JSONB 保存改动前后的字段值，时间线页面可逐项展开查看。

### 四象限

- 以「重要 × 紧急」两个维度划分 **Q1 重要紧急 / Q2 重要不紧急 / Q3 紧急不重要 / Q4 不重要不紧急**。
- 支持跨象限拖拽，并可用原生 HTML5 拖放完成。
- **拖拽不静默改写优先级** —— 象限变化只返回一个建议优先级，由用户二次确认后才应用。

### 视图

| 页面 | 职责 |
| --- | --- |
| 仪表盘 | 概览读数、新增/完成趋势、象限分布、今日待办与快捷入口 |
| 任务列表 | 多维筛选、排序、分页、批量操作 |
| 四象限 | 2×2 看板，快速完成 / 编辑 / 删除 / 跨象限拖拽 |
| 日历 | 按月展示任务分布，逾期日期高亮，侧栏查看当日明细 |
| 时间线 | 操作日志按日期倒序分组，支持按操作类型筛选 |
| 统计 | 时间范围切换、完成率与逾期率、趋势图、象限饼图、标签分布 |
| 设置 | 账户与密码、偏好配置、标签管理、导出导入、备份恢复、数据清空 |

### 数据能力

- **用户级隔离** —— 所有业务表带 `user_id`，标签与配置项按用户维度唯一，不同用户可使用同名标签而不冲突。
- **导出 / 导入** —— 完整导出任务、标签、关联与日志为 JSON；导入时按标题与名称去重，并重建旧 ID 到新 ID 的映射，使关联数据和日志能正确挂载。
- **备份 / 恢复** —— 服务端落盘备份，恢复复用导入链路；备份与恢复均校验归属，无法访问他人备份。
- **数据清空** —— 清空当前用户的全部业务数据后，自动重建默认配置。

## 快速开始

### 环境要求

| 组件 | 版本 |
| --- | --- |
| JDK | 17 及以上 |
| Maven | 3.6.3 及以上（或直接使用项目自带的 `mvnw`） |
| Node.js | 20 及以上 |
| PostgreSQL | 12 及以上 |

### 1. 准备数据库

```sql
CREATE DATABASE todo_db;
```

表结构由 Flyway 在应用启动时自动创建，**请勿手工改表**。

### 2. 配置后端

```bash
cd backend
cp src/main/resources/application-dev.yml.example src/main/resources/application-dev.yml
```

然后编辑 `application-dev.yml`，填入数据库的 `host` / `port` / `username` / `password`。

> 该文件已在 `.gitignore` 中，不会被提交。

### 3. 启动后端

```bash
cd backend
./mvnw spring-boot:run
```

首次启动会自动完成建表、创建管理员账号与初始化默认配置。

- 服务地址：`http://localhost:8080`
- 接口文档：`http://localhost:8080/swagger-ui.html`

> **⚠️ 默认管理员为 `admin / admin123`，请在首次登录后立即修改密码。**

### 4. 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问 `http://localhost:5173`。

> 开发期前端不使用 Vite 代理，而是按当前页面主机名拼接 `:8080` 直连后端，
> 因此用 `localhost`、`127.0.0.1` 或局域网 IP 打开页面均可连上同一后端。
> 后端不在本机时，用环境变量 `VITE_API_BASE_URL` 覆盖。

## 设计要点

### 状态机

```
待办(0)   → 进行中(1) / 已完成(2) / 已取消(3)
进行中(1) → 待办(0) / 已完成(2) / 已取消(3)
已完成(2) → 待办(0)     （重新打开）
已取消(3) → 待办(0)     （恢复）
```

流转白名单集中在一个纯静态类中，Service 不重复实现规则；前端下拉选项由同一份定义生成，两侧不会漂移。

### 逾期不落库

数据库中没有「已逾期」这个状态。逾期是**查询时派生的计算结果**：待办与进行中的任务，截止时间已过即为逾期；已完成的任务，完成时间晚于截止时间即为逾期完成。

这样做避免了需要定时任务去刷新状态，也不会出现"库里状态与真实时间脱节"的问题。

### 错误响应约定

**HTTP 状态码与响应体中的业务码保持一致**（`400` / `401` / `404` / `409` / `413` / `415` / `422` / `500`），前端拦截器据此统一提取提示信息。

### 数据隔离

认证拦截器校验 JWT 后将用户标识写入线程上下文，各服务层的查询条件显式带上 `user_id`。

> 注意：这是**显式隔离**而非全局兜底——新增查询时必须自行补上用户条件。

## 接口概览

所有接口以 `/api` 为前缀，除登录与注册外均需 `Authorization: Bearer <token>`。

| 模块 | 前缀 | 说明 |
| --- | --- | --- |
| 认证 | `/api/auth` | 登录、注册、当前用户、改昵称、改密码 |
| 任务 | `/api/tasks` | 增删改查、状态流转、象限变更、拖拽排序、批量操作 |
| 四象限 | `/api/quadrant` | 看板数据 |
| 统计 | `/api/stats` | 概览、趋势、象限分布、标签分布、完成率 |
| 日历 | `/api/calendar` | 日历任务与热力图 |
| 时间线 | `/api/timeline` | 操作日志 |
| 标签 | `/api/tags` | 标签增删改查 |
| 配置 | `/api/config` | 系统偏好读写 |
| 数据迁移 | `/api/migration` | 导出、导入、备份、恢复、清空 |

## 开发与测试

### 数据库变更

**禁止手工改表。** 变更流程：

1. 在 `backend/src/main/resources/db/migration/` 下新增 `V{n}__{描述}.sql`
2. 重启应用，Flyway 自动执行

### 运行测试

```bash
cd backend
./mvnw clean test
```

测试覆盖接口行为与数据库结构两方面，后者会连接真实数据库校验表、约束、索引与触发器是否正确建立。

> 部分测试需要可用的数据库连接，运行前请确保 `application-dev.yml` 配置正确。

### 前端构建

```bash
cd frontend
npm run build
```

## 已知限制

- **开发期 CORS 默认放行**。生产环境应通过反向代理做同源部署，并收紧来源白名单。
- **前端主包体积约 1 MB**（gzip 后约 350 KB），主要来自 Element Plus 全量引入，可改用按需引入优化。
- **备份文件存放在本地磁盘**，尚未支持对象存储；多实例部署时需共享存储。
- **数据隔离依赖各查询显式带条件**，没有全局兜底机制。
